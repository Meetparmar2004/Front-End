Task 3: Update Order Records Using Update Operators
----------------------------------------------------

Question:
Modify existing order documents in the orders collection to reflect real-time status changes in the QuickEats delivery workflow.
- Use updateOne with $set to change the status of one 'pending' order to 'confirmed' and add a confirmedAt field set to the current date.
- Use updateMany with $set to mark all 'confirmed' orders as 'delivered' (simulate a batch dispatch update).
- Use $push to add a new entry {event: 'dispatched', time: new Date()} to a deliveryLog array inside one specific order document.
- Use $unset to remove the confirmedAt field from at least one order. Verify all changes by running find() queries after each update.

Answer:

// 1. updateOne with $set — one pending order to confirmed + confirmedAt
->  db.orders.updateOne(
      { status: "pending" },
      {
        $set: {
          status: "confirmed",
          confirmedAt: new Date()
        }
      }
    )

->  db.orders.find({ status: "confirmed" })

// 2. updateMany with $set — all confirmed orders to delivered
->  db.orders.updateMany(
      { status: "confirmed" },
      { $set: { status: "delivered" } }
    )

->  db.orders.find({ status: "delivered" })

// 3. $push — add dispatched entry to deliveryLog on one specific order
->  db.orders.updateOne(
      { customerId: "C001" },
      {
        $push: {
          deliveryLog: {
            event: "dispatched",
            time: new Date()
          }
        }
      }
    )

->  db.orders.find({ customerId: "C001" })

// 4. $unset — remove confirmedAt from at least one order
->  db.orders.updateOne(
      { confirmedAt: { $exists: true } },
      { $unset: { confirmedAt: "" } }
    )

->  db.orders.find({ confirmedAt: { $exists: true } })



Task 4: Restaurant Revenue Report Using Aggregation
----------------------------------------------------

Question:
Build a multi-stage aggregation pipeline on the orders collection to generate a restaurant-wise revenue summary for the QuickEats admin panel.
- Use $match as the first stage to filter only orders with status 'delivered'.
- Use $group to group filtered orders by restaurantName, computing totalRevenue as the sum of totalAmount and orderCount as the count of documents per group.
- Use $project to shape the output: display restaurantName, totalRevenue, and orderCount; suppress the default _id field.
- Use $sort to sort the final output by totalRevenue descending, then $limit to show only the top 3 restaurants. Run the pipeline and screenshot the result.

Answer:

->  db.orders.aggregate([
      {
        $match: {
          status: "delivered"
        }
      },
      {
        $group: {
          _id: "$restaurantName",
          totalRevenue: { $sum: "$totalAmount" },
          orderCount: { $sum: 1 }
        }
      },
      {
        $project: {
          _id: 0,
          restaurantName: "$_id",
          totalRevenue: 1,
          orderCount: 1
        }
      },
      {
        $sort: {
          totalRevenue: -1
        }
      },
      {
        $limit: 3
      }
    ])
