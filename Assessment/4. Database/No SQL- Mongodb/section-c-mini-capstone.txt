Section C — Mini Capstone Project
==================================


Question:
Build a complete MongoDB database for a food delivery platform called QuickEats, combining CRUD operations, query operators, update operators, aggregation pipelines, and indexing into a single cohesive system that simulates a real delivery backend.

Your project must:
1. Create a database quickeats_db with three collections: restaurants, orders, and customers. Each collection must have at least 5 realistic documents with meaningful nested fields (e.g. a menu array in restaurants, an items array in orders, an addresses array in customers).
2. Write at least 3 read queries using a combination of $gt, $lt, $in, $eq, and projection — covering scenarios such as finding restaurants with rating above 4, filtering orders by status, and listing customers from a specific city.
3. Write at least 3 update operations using $set, $push, and $inc — covering scenarios such as updating an order status, appending to a delivery log array, and incrementing a loyaltyPoints field on a customer document.
4. Build an aggregation pipeline that produces a revenue report: use $match for delivered orders, $group by restaurantName for total revenue and order count, $project for clean output, and $sort by revenue descending.
5. Create a compound index on {customerId: 1, status: 1} in the orders collection. Run explain('executionStats') on a filtered query before and after creating the index, and include a screenshot showing the difference in totalDocsExamined.

Part 2 — At least 3 read queries ($gt, $lt, $in, $eq, projection)
-------------------------------------------------------------------

// Query 1: restaurants with rating above 4 — uses $gt + projection
->  db.restaurants.find(
      { rating: { $gt: 4 } },
      { name: 1, rating: 1, city: 1, _id: 0 }
    )

// Query 2: orders filtered by status — uses $in + projection
->  db.orders.find(
      { status: { $in: ["pending", "confirmed"] } },
      { customerId: 1, restaurantName: 1, status: 1, totalAmount: 1, _id: 0 }
    )

// Query 3: customers from a specific city — uses $eq + projection
->  db.customers.find(
      { city: { $eq: "Pune" } },
      { name: 1, email: 1, loyaltyPoints: 1, _id: 0 }
    )

// Query 4: using $lt — orders under Rs 300
->  db.orders.find(
      { totalAmount: { $lt: 300 } },
      { customerId: 1, totalAmount: 1, _id: 0 }
    )


Part 3 — At least 3 update operations ($set, $push, $inc)
----------------------------------------------------------

// Update 1: $set — update order status from pending to confirmed
->  db.orders.updateOne(
      { status: "pending" },
      { $set: { status: "confirmed", confirmedAt: new Date() } }
    )

// Update 2: $push — append entry to delivery log array on an order
->  db.orders.updateOne(
      { customerId: "C003" },
      {
        $push: {
          deliveryLog: {
            event: "out_for_delivery",
            time: new Date()
          }
        }
      }
    )

// Update 3: $inc — increment loyaltyPoints on a customer after order
->  db.customers.updateOne(
      { name: "Rahul Sharma" },
      { $inc: { loyaltyPoints: 10 } }
    )


Part 4 — Revenue aggregation pipeline
--------------------------------------

->  db.orders.aggregate([
      {
        $match: { status: "delivered" }
      },
      {
        $group: {
          _id: "$restaurantName",
          totalRevenue: { $sum: "$totalAmount" },
          orderCount: { $sum: 1 }
        }
      },
      {
        $project: {
          _id: 0,
          restaurantName: "$_id",
          totalRevenue: 1,
          orderCount: 1
        }
      },
      {
        $sort: { totalRevenue: -1 }
      }
    ])


Part 5 — Compound index + explain before and after
---------------------------------------------------

// BEFORE creating index — run explain on filtered query
->  db.orders.find({
      customerId: "C001",
      status: "delivered"
    }).explain("executionStats")

// Create compound index on orders collection
->  db.orders.createIndex({ customerId: 1, status: 1 })

// AFTER creating index — same query with explain
->  db.orders.find({
      customerId: "C001",
      status: "delivered"
    }).explain("executionStats")
